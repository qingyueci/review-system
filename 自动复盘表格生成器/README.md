# 复盘布局分析器

本地复盘工具，包含四条功能链路：

1. 自动抓取延边刺客指定日期的公开复盘，调用 Kimi Code 生成单工作表 Excel。
2. 首次建立时扫描最近一年公开主帖并固定前 20 篇；之后只增量维护近期 10 篇，建立持续积累的本地 RAG 知识库。
3. 同一份清洗后的每日复盘会并行进入两条独立链路：原格式 Excel 完整整理，以及按“首板出身—个股任务—布局关系—地位变化”生成 Word 核心分析。
4. 自动读取上一级目录中的 `延边刺客短线打板体系.docx`，清洗、分段后作为人工整理体系加入 RAG。

## 运行

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python -m streamlit run app.py
```

浏览器打开 Streamlit 给出的本地地址。

## 首次使用顺序

1. 在“知识库”页面点击“增量更新近期 10 篇”；首次使用会同时建立固定核心 20 篇。
2. 在“今日复盘”页面选择日期，点击“获取该日公开复盘”。
3. 填写 Kimi Code API Key，选择“同时生成 / 只生成 Excel / 只生成 Word”。
4. 两个结果会分别保存；任一链路因额度或网络失败时，另一条成功结果仍会保留。
5. 失败项可以单独重试，不会重复调用已经成功的模型链路。
6. 相同复盘仍在生成时，重复点击会自动接回原任务，不会再次调用模型。

## 采集和清洗

- 只访问无需登录即可查看的公开页面，不绕过登录或验证码。
- 首次建立时从移动博客公开分页发现最近一年帖子，按页面显示浏览量排序后固定前 20 篇。
- 主帖正文完整入库。
- 高阅读量核心 20 篇建立后完全冻结：日常更新不重新扫描、不刷新、不重排。
- 日常只发现和刷新近期 10 篇；移出近期窗口的帖子降级为历史归档，正文、回复和清洗片段全部保留，仍可检索但权重降低。
- 不使用“只看楼主”、Cookie 或积分权限。高评论量帖子默认最多抽取 12 个公开评论页，覆盖开头、结尾及中间均匀位置。
- 延边刺客本人的有效公开回复优先入库；其他用户评论按点赞量、内容信息量和布局关键词相关度筛选，默认每篇最多 20 条。
- 每篇同时读取公开“点赞榜”，其中延边刺客本人的有效评论全部保留，其他评论继续按点赞和布局相关度筛选。
- 已通过登录浏览器补全的旧帖会标记为“登录浏览器完整抓取”，后续公开同步不会用正文节选覆盖它。
- 社区评论始终标成“社区精选评论”，仅作为常见疑问和市场共识的辅助材料，不代表延边刺客观点。
- 问题与回复保存在同一个检索单元，原帖、楼层、时间和链接均保留。
- 检索采用关键词 BM25 与本地轻量向量的候选合并，再按来源、时间和题材概念综合排序。
- 来源权重依次为：本人回复 1.00、历史主帖 0.90、人工体系 0.82、社区评论 0.55；社区评论不能覆盖作者原文。
- 数据保存在 `data/review_knowledge.db`；近期帖子评论数未变化时直接复用，历史归档帖不再重复爬取。
- 本地体系文件按内容哈希增量更新；未修改时直接复用。它用于补足概念和执行规则，若与作者公开原文冲突，以原帖和本人回复为准。

## 分析原则

模型提示词明确禁止用普通技术分析覆盖布局逻辑。Word 只分析真正有任务、地位或辨识度的核心个股，默认不超过 6 只，复杂盘面最多 8 只；其余首板完整保留在 Excel 中。分析顺序固定为：

1. 首板出身与发酵来源。
2. 个股原始任务。
3. 个股之间的协同、压制和反推关系。
4. 主动性、带动性、独立性与市场地位变化。
5. 任务完成或失败。
6. 次日竞价确认和判断失效条件。

价格、量能、均线等只能作为任务是否完成的验证证据。

## 配置

- `KIMI_API_KEY`：必填，也可在页面临时填写。
- `KIMI_BASE_URL`：默认 `https://api.kimi.com/coding/v1`。
- `KIMI_MODEL`：默认 `kimi-for-coding`。
- `KIMI_TIMEOUT`：模型请求超时秒数，默认 300。
- `TGB_TIMEOUT`：网页请求超时秒数，默认 20。
- `TGB_INTERVAL`：两次网页请求的最小间隔，默认 0.35 秒。
- `TGB_MAX_RETRIES`：网页请求重试次数，默认 3。
- `TGB_MAX_LIST_PAGES`：发现近一年主帖时最多扫描的分页数，默认 60。
- `TGB_MAX_COMMENT_PAGES`：每篇帖子最多抽取的评论页数，默认 12。
- `TGB_TOP_POST_LIMIT`：近一年高阅读量核心帖数量，默认 20。
- `TGB_COMMUNITY_MIN_LIKES`：社区评论直接进入候选的最低点赞数，默认 5；高度相关的低赞评论可酌情进入。
- `TGB_COMMUNITY_MAX_PER_POST`：每篇帖子最多保留的社区高赞评论数，默认 20。
- `REVIEW_MANUAL_SYSTEM_DOCX`：人工整理体系 Word 文件路径；默认读取软件目录上一级的 `延边刺客短线打板体系.docx`。
- `REVIEW_JOB_DB`：生成任务记录数据库路径；默认保存在本机 `data/review_jobs.db`。

API 密钥只从环境变量或密码输入框读取，不写入 Excel、Word 或知识库。
本机默认保留最近 100 条生成任务；超出后只清理已经结束的旧任务。

## 复盘驾驶舱

双击 `启动复盘驾驶舱.cmd`，程序会：

1. 启动仅监听 `127.0.0.1` 的本机服务。
2. 用随机本机令牌打开私有驾驶舱站点。
3. 允许站点调用本地知识库、自爬取、清洗，以及并行生成 Excel 和 Word。
4. 启动器会自动识别旧版本本机服务并重启，避免页面仍连接到旧功能。
5. 生成任务会记录到本机数据库；服务重启后仍能查看最近结果和失败原因。
6. “历史文档”页面同时显示运行记录，包括两条生成链路的耗时、引用资料、失败类型和模型返回的 token 用量。

模型供应商未返回 token 用量时，页面会明确显示“供应商未返回”，不会估算或伪造消耗。

知识库与 API Key 不会上传到站点。若 `.env` 未配置 `KIMI_API_KEY`，可在驾驶舱中临时填写，密钥只会发送给本机服务。

## 代码结构

- `api.py`：只保留本机接口、权限校验和流程入口。
- `task_manager.py` / `job_store.py`：任务内存状态与 SQLite 持久化。
- `artifact_store.py`：Excel、Word 的保存、列表和安全下载。
- `generation_service.py`：清洗后的复盘并行进入 Excel 与 Word 生成链路。
- `review_input.py` / `schemas.py`：文件读取与接口请求模型。
- `analysis_parser.py`：把 Word 分析内容拆成页面可展示的结构。

前端页面也按“今日复盘、布局分析、知识库、历史文档”拆为独立组件，页面入口只负责状态和流程编排。
